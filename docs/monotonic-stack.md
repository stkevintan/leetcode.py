# 单调栈：从"怎么用"到"为什么"

---

## 一、单调栈的本质

单调栈维护一组元素，保持**单调递增**或**单调递减**。当新元素破坏单调性时，弹出栈顶——**弹出的那一刻，被弹出元素的"命运"被新元素决定了**。

---

## 二、两种计算时机

### 模式 A：弹出时算（被弹出者是主角）

被弹出元素的**范围到此为止**，新元素是它的边界。

```
      ██
    ████        ← 4 来了，3 被弹出
  ██████        → 3 的右边界 = 4 的位置
████████
  ↑    ↑
 left  i
```

**适用**：需要同时看到左右边界的题

| 题号 | 题目 | 弹出时算什么 |
|------|------|------------|
| 84 | 柱状图最大矩形 | 以弹出高度为最矮的矩形面积 |
| 42 | 接雨水 | 弹出者作为凹槽底部的积水量 |
| 85 | 最大矩形 | 84 的二维版 |

```python
# 核心模板
while stack and heights[stack[-1]] > h:
    j = stack.pop()
    left = stack[-1] if stack else -1     # 左边界(栈里下一个)
    ans = max(ans, heights[j] * (i - left - 1))  # 右边界 = i
```

### 模式 B：压入时算（被压入者是裁判）

新元素的到来，**解救了栈里等待的旧元素**。

```
stack → [等待者1, 等待者2, 等待者3]
push →   🔥答案来了！
         栈里所有更小的都得到答案
```

**适用**：只需要看一侧的题

| 题号 | 题目 | 压入时算什么 |
|------|------|------------|
| 739 | 每日温度 | 栈里元素的下一个更高温度距离 |
| 496 | 下一个更大元素 I | 栈里元素的下一个更大值 |
| 503 | 下一个更大元素 II | 同上，循环数组版 |

```python
# 核心模板
for i, t in enumerate(temperatures):
    while stack and t > temperatures[stack[-1]]:
        j = stack.pop()
        ans[j] = i - j    # 新元素的到来决定了旧元素的答案
    stack.append(i)
```

## 三、方向对称性：正向 vs 逆向

同一道题，倒过来遍历，计算时机可能**翻转**。

```
正向:  新元素 ①→②→③→④  栈里存"过去"
逆向:  新元素 ④→③→②→①  栈里存"未来"
```

### 739. 每日温度

| | 正向 | 逆向 |
|---|---|---|
| 遍历方向 | `0 → n-1` | `n-1 → 0` |
| 栈里存什么 | 还没找到答案的"待解救者" | 未来的"答案库" |
| 新元素角色 | 来解救栈里的人 | 来查询栈里的答案 |
| 计算时机 | **pop 时算** | **append 时算** |

```python
# 正向（模式 B，pop 时算）
for i, t in enumerate(temperatures):
    while stack and t > temperatures[stack[-1]]:
        j = stack.pop()
        ans[j] = i - j
    stack.append(i)

# 逆向（模式 B 翻转，append 时算）
for i in range(n - 1, -1, -1):
    while stack and temperatures[stack[-1]] <= temperatures[i]:
        stack.pop()
    if stack:
        ans[i] = stack[-1] - i    # 栈顶就是答案
    stack.append(i)
```

### 84. 柱状图最大矩形

这道题无论正向还是逆向，**都是 pop 时算**。因为矩形的面积需要同时知道左边界和右边界，缺一不可。

| | 正向 | 逆向 |
|---|---|---|
| pop 触发 | 矮柱子出现（右边界确定） | 矮柱子出现（左边界确定） |
| 已知边界 | 左边界(栈内) | 右边界(栈内) |
| 新来的是 | 右边界 | 左边界 |
| 收尾 | 需要（末尾哨兵 0） | 需要（开头哨兵 0） |

## 四、核心洞察：视野决定时机

为什么 739 倒过来可以 "append 时算"，84 倒过来却不行？

```
739. 每日温度          84. 柱状图最大矩形
视野: 柱子 →          视野: ← 柱子 →
单向，只需看右边       双向，需要左右边界
                           ↓
倒过来：右边在栈里      倒过来：右边在栈里，但左边还没出现
→ 看一眼栈顶就行        → 还是得等左边出现（pop 时算）
```

> **看一边**的题，倒过来可以把答案提前准备好 → append 时算  
> **看两边**的题，无论怎么倒，缺的那一侧没出现之前永远算不了 → pop 时算

## 五、哨兵技巧

在数组开头/末尾补一个极小值，让所有元素自然弹出，省去收尾循环。

```python
# 84 题正向：末尾补 0
heights.append(0)
for i, h in enumerate(heights):
    while stack and heights[stack[-1]] > h:
        j = stack.pop()
        left = stack[-1] if stack else -1
        ans = max(ans, heights[j] * (i - left - 1))
    stack.append(i)

# 84 题逆向：开头补 0
heights.insert(0, 0)
# 其余逻辑镜像...
```

## 六、接雨水 (42) 的特殊性

接雨水有两种单调栈写法，对应两种"理解世界"的方式：

### 写法 1：base 层累加法

```python
base = 0
while stack and height[stack[-1]] <= v:
    p = stack.pop()
    ans += (i - p - 1) * (height[p] - base)  # 只算比 base 多出的一层
    base = height[p]                           # 逐层向上
if stack:
    ans += (v - base) * (i - stack[-1] - 1)
```

### 写法 2：凹槽法（更直觉）

```python
while stack and height[stack[-1]] < h:
    bottom = stack.pop()          # 凹槽底
    if not stack: break
    left = stack[-1]              # 左墙
    w = i - left - 1
    hh = min(height[left], h) - height[bottom]  # 水深 = 矮墙 - 槽底
    ans += w * hh
```


## 九、最小字典序双雄：402 移掉 K 位数字 vs 316 去除重复字母

两题同源：**用单调栈保序删字符，求最小字典序结果**。但约束不同，弹栈条件、结尾处理各不相同，放一起对比能彻底吃透。

### 共同骨架

```
遍历字符 c:
    while 弹栈条件: pop()
    append(c)
结尾处理
```

贪心直觉一样：**栈顶比当前字符大且还删得起 → 弹掉**。高位（栈底）越早变小，字典序越占便宜。

### 402：恰好删 k 个

```python
def removeKdigits(self, num: str, k: int) -> str:
    stack = []
    for c in num:
        while k > 0 and stack and stack[-1] > c:
            stack.pop()
            k -= 1
        stack.append(c)
    while k > 0:                 # 还能删：栈单调不减，末尾最大
        stack.pop()
        k -= 1
    ans = ''.join(stack).lstrip('0')
    return ans or '0'
```

- **弹栈条件**：`k > 0`（还有删除额度）；
- **去重**：无——数字重复出现是合法的；
- **结尾**：k 没花完时从**末尾**删（此时栈单调不减，越靠右越大）；
- **前导零**：`lstrip('0')`，全删光返回 `"0"`。

### 316：每个字符恰好一次

```python
def removeDuplicateLetters(self, s: str) -> str:
    cnt = Counter(s)
    instack = set()
    stack = []
    for c in s:
        if c in instack:
            cnt[c] -= 1          # 重复出现只留第一次
            continue
        while stack and stack[-1] > c and cnt[stack[-1]] > 0:
            instack.discard(stack.pop())
        stack.append(c)
        instack.add(c)
        cnt[c] -= 1
    return "".join(stack)
```

- **弹栈条件**：`cnt[栈顶] > 0`（它后面还会出现，弹出后能补回来）；
- **去重**：`instack` 保证每个字符只入栈一次；
- **结尾**：无需处理——弹栈条件 `cnt > 0` 保证每个字符至少剩一次；
- **前导零**：无此概念。

### 对比表

| | 402 | 316 |
|---|---|---|
| 目标 | 删 k 个字符，数字最小 | 每字符恰好一次，字典序最小 |
| 数量约束 | **恰好 k 个** | **每个字符 1 次** |
| 弹栈的「额度」 | `k > 0` | `cnt[栈顶] > 0` |
| 去重 | 不需要 | `instack` + 遇重 `cnt -= 1` |
| 结尾处理 | 剩余 k 从末尾删 | 不需要 |
| 特殊输出 | 去前导零，空则 `"0"` | 直接拼接 |

### 一句话本质

> 两题都是「**最小字典序的保序筛选**」：402 的预算按**个数**计（k），316 的预算按**出现次数**计（cnt）。预算花在哪？都花在「弹掉比当前大的栈顶」上——区别只在于怎么判断「还弹得起」。
