# 背包循环顺序：组合数 vs 排列数

> 为什么 518（组合数）与 377（排列数）代码几乎一样，只有循环嵌套顺序不同？

---

## 一、两段几乎相同的代码

```python
# 518 零钱兑换 II —— 组合数（顺序无关）
dp = [0] * (amount + 1); dp[0] = 1
for coin in coins:              # 硬币在外层
    for j in range(coin, amount + 1):
        dp[j] += dp[j - coin]

# 377 组合总和 IV —— 排列数（顺序有关）
dp = [0] * (amount + 1); dp[0] = 1
for j in range(amount + 1):     # 金额在外层
    for coin in coins:
        if j >= coin:
            dp[j] += dp[j - coin]
```

| | 518 组合数 | 377 排列数 |
|---|---|---|
| 外层 | 硬币 | 金额 |
| `[1,2]` 凑 `3` | 2 种：`{1+1+1, 1+2}` | 3 种：`{1+1+1, 1+2, 2+1}` |

---

## 二、硬币在外层：为什么是组合

处理第 `i` 枚硬币时，`dp[j-coin]` 里只包含**用前 `i` 枚硬币**凑出的方案。当前硬币永远被**追加在既有方案末尾**，且每枚硬币只处理一次、不再回头。

效果：硬币的使用顺序被固定为外层遍历顺序，同一个多重集合只会被构造一次。

```
coins=[1,2], amount=3

处理 coin=1 后: dp = [1,1,1,1]       {1+1+1}
处理 coin=2 后: dp[3] += dp[1] → 2   {1+1+1, 1+2}
dp[3] = 2     ← 2+1 与 1+2 算同一种
```

## 三、金额在外层：为什么是排列

算 `dp[j]` 时，`dp[j-coin]` 已经包含**所有硬币**构造出的方案。对每个 coin，都在这些方案的末尾**再接一个 coin**——不同 coin 接在不同位置，同一集合的不同顺序就被分别生成了一次。

```
for j in 1..3:
  for coin in [1,2]:
    dp[j] += dp[j-coin]

j=2: dp[2] = dp[1](接1) + dp[0](接2) = 2   {1+1, 2}
j=3: dp[3] = dp[2](接1) + dp[1](接2) = 3   {1+1+1, 2+1, 1+2}
dp[3] = 3     ← 2+1 与 1+2 被当成两种
```

`j=3, coin=1` 那一步：`dp[2]` 里包含"以 2 结尾"的方案，尾接 1 产生 `2,1`；`j=3, coin=2` 那一步从 `dp[1]` 尾接 2 产生 `1,2`。两个顺序都被计数 → 排列数。

---

## 四、延伸：j 的正序与倒序（01 背包 vs 完全背包）

同一个"硬币外层"框架下，内层 `j` 的方向决定物品能用几次：

```python
# 01 背包：j 倒序 —— dp[j-coin] 还是"上一行"的旧值，当前硬币未被计入 → 每件只用一次
for coin in coins:
    for j in range(amount, coin - 1, -1):
        dp[j] += dp[j - coin]

# 完全背包：j 正序 —— dp[j-coin] 已被当前硬币更新过 → 可重复使用
for coin in coins:
    for j in range(coin, amount + 1):
        dp[j] += dp[j - coin]
```

| 循环写法 | 物品次数 | 计数口径 | 典型题 |
|---|---|---|:---:|
| 硬币外层 + j 倒序 | 每件一次（01） | 组合 | 416、494 |
| 硬币外层 + j 正序 | 无限（完全） | 组合 | 518、322 |
| 金额外层 + 硬币内层 | 无限（完全） | 排列 | 377 |

---

## 五、一句话总结

- **外层枚举物品** = 固定物品加入顺序 → 组合；**内层枚举物品** = 每个容量重新挑选 → 排列。
- **j 正序** = 当前物品可重复（完全背包）；**j 倒序** = 每件至多一次（01 背包）。
